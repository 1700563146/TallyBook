# TallyBook 隐患清单（Risk Register）

> 本文件是**活的清单**：每发现一个真实缺陷或一个未经缓解的风险，就在这里留一条记录。
>
> 分三部分：**A. 已确认并修复**（含证据，用于防止回归）、**B. 已知未修复**（按严重度）、
> **C. 产品与工程风险**（不写代码也要有对策）。
>
> 图例：🔴 严重（数据错误/崩溃/隐私） · 🟠 中（功能失真或明显体验问题） · 🟡 低（打磨/技术债）
> 状态：✅ 已修复 · ⚠️ 未修复 · 📋 需产品决策

---

## A. 已确认并修复的缺陷

这几条都**真实发生过**，不是假设。保留它们的原因是：每一条都对应一个"看起来没问题"的写法，
而它们共同的特征是**不会报错**。

### A1. 周视图图表永远为 0（SQL 与 Kotlin 的分桶语义不一致）🔴 ✅

**现象**：周粒度趋势图所有数据点读成 0，不崩溃、无日志。

**根因**：分桶做了两次，两次的定义不同。

| 侧 | 表达式 | 语义 |
| --- | --- | --- |
| SQL | `strftime('%W')` | 年内第几个周一；首个周一之前是 `00` |
| Kotlin | `WeekFields.of(Locale.UK)` | ISO 周历（week-based year，首周至少 4 天） |

**实测**（SQLite + JVM 日期对照，2024-01-01 ~ 2026-01-10 共 753 天）：
**377 天（50.1%）两侧键值不同**。

```
2024-12-30 Mon  SQL: 2024-W53   Kotlin: 2025-W01
2025-01-01 Wed  SQL: 2025-W00   Kotlin: 2025-W01
2025-01-06 Mon  SQL: 2025-W01   Kotlin: 2025-W02
```

SQL 只返回有数据的桶，Kotlin 用另一套键去查，**查不到就填 0** —— 于是图表全零。

**为什么原测试没抓到**：`BucketKeyConsistencyTest` 只断言了 Kotlin 侧"能生成自己认为对的键"，
从未与 SQL 对拍。它是实现的重述，不是一致性测试。

**修复**：
1. SQL 只聚合到**天**（`strftime('%Y-%m-%d')`，ISO 日期无歧义）。
2. 周/月/年分组全部由 `DateProvider.bucketStartOf()` 在 Kotlin 完成，
   与预算共用同一个 `weekStartsOn`。
3. 新增 `TrendBucketerTest`（11 例），直接覆盖跨年周、闰日、空桶补零、边界外数据。

**教训**：**一致性测试必须同时驱动接缝的两端。** 只测一边等于没测，还会给人虚假的安全感。
另一层教训是：同一个概念（"哪一周"）只能有**一个**实现。

### A2. `Money.plus` 加错操作数，所有金额累加恒错 🔴 ✅

**现象**：`10 + 20 = 20`；`0 + 0 = 0`；累加 1000 次 1 分得到 `0`。

**根因**：为了让调用点短一点，守卫函数返回了参数：

```kotlin
private fun requireSameCurrency(other: Money): Money { ...; return other }

fun plus(other: Money) =
    copy(minorUnits = Math.addExact(minorUnits, other.requireSameCurrency(this).minorUnits))
//                                          ^^^^^ 这里拿到的是「接收者 this」，不是 other
```

**修复**：守卫函数改为返回 `Unit`，强制每个运算点显式写出两个操作数。

```kotlin
fun plus(other: Money): Money {
    requireSameCurrency(other)
    return copy(minorUnits = Math.addExact(minorUnits, other.minorUnits))
}
```

**教训**：辅助函数"顺手返回值"来省字符，会把调用点变成**一维易错形态**。
测试是唯一抓到它的东西。

### A3. 转账写两行 → 账户余额永远不变 🔴 ✅

**现象**：从 A 转 100 到 B，两个账户余额都不变。

**根因**：两种转账表示共存且互相抵消。

- 领域模型：**一行**记录，带 `counterAccountId`
- `insertTransferPair`：写了**两行**互相镜像的记录

余额查询对每个账户既算 `account_id` 又算 `counter_account_id`，
两行镜像相加后 +100 与 −100 抵消为 0。

**修复**：删除 `insertTransferPair`，只保留 `upsertTransfer`（单行），并在 DAO 注释里写清
"没有两行变体，这是设计"。

**教训**：**同一事实只能有一种存储形状。** 如果两种表示都能表达同一件事，
迟早会有人同时用上。

### A4. `BudgetViewModel.refresh()` 泄漏收集器 🟠 ✅

**现象**：每次 `refresh()` 都启动一个新的 `collect`，旧的不取消。

**后果**：onResume / 下拉刷新 / 旋转各调一次就多一个永不停止的收集器，多个收集器竞争写
`_uiState`，表现为数字闪烁 + 重复查询，且要等 ViewModel 销毁才释放。

**修复**：持有 `progressJob`，先 `cancel()` 再启动。

**教训**：**任何在函数里 `launch { flow.collect() }` 的写法，都要问一句"谁负责取消"。**

---

### A5. 预算周期首日 `daysElapsed = 0` 🟠 ✅

**现象**：每月 1 日打开预算，"还剩 0 天"、进度比率除零。

**修复**：首日计为 1 天（`nowMillis < startMillis` 才返回 0），并有测试锁定。

**教训**：周期边界要么"含两端"，要么"左闭右开"，**每个函数都要明确选一个并写进注释**。
这个 bug 源于同一个类里两种约定混用。

### A6. 撤销后用户看不到任何变化 🟠 ✅

**现象**：长按删除一行后点"撤销"，合计金额恢复了，但那一行没有出现 —— 看起来撤销没生效。

**根因**：`LazyColumn` 会锚定第一个可见项。行被恢复后插到视口**上方**，列表保持原来的滚动位置，
用户看到的画面完全没变。

**修复**：`undoDelete()` 递增 `scrollToTopTick`，界面监听它并 `animateScrollToItem(0)`。

**教训**：**数据流对了，不等于用户感知对了。** 列表插入/恢复类操作必须处理滚动锚定，
否则"功能正常"只存在于日志里。

### A7. 金额符号随设备语言变化 🟠 ✅

**现象**：同一份 CNY 数据，中文设备显示 `¥123.45`，英文设备显示 `CN¥123.45`，
在窄列表行里还会挤掉备注。

**根因**：`NumberFormat.getCurrencyInstance()` 的符号来自**设备 locale**，而账本排版不应随系统语言漂移。

**修复**：符号按币种显式映射（CNY→`¥`、USD→`$`、JPY→`¥`…），未知币种才回落到 JDK；
数字分组与小数位仍取 locale，保留逗号/小数点差异。

**教训**：**格式化函数的输出是产品的一部分**，不能把它交给平台默认值。

---

### A8. 反引号测试名导致仪器化测试无法编译 🟠 ✅

**现象**：`:core:database:connectedDebugAndroidTest` 在 dex 阶段失败：
`Space characters in SimpleName 'TransactionAggregatesTest$restore brings a soft deleted row back$1' are not allowed prior to DEX version 040`。

**根因**：Kotlin 允许 `fun \`transfers move money\`()`，可读性很好；但编译器为 lambda 生成内部类时
会把方法名原样带进类名，而 D8 对 DEX < 040（即 `minSdk < 30`）拒绝含空格的类名。
**测试还没开始跑就失败了**，且错误信息指向的是编译产物而不是写法。

**修复**：`androidTest` 里的方法名改为 snake_case；纯 JVM 模块保留反引号命名（不受影响）。

**教训**：**平台限制会在"最不该出问题"的地方冒出来** —— 单元测试命名这种纯收益的写法，
换到仪器化环境就成了编译错误。这也是保留两层测试（JVM + 真机）的价值：
问题暴露在构建期而不是发版后。

---

### A9. 测试运行器自身成为障碍（Robolectric → 仪器化）🟡 ✅

**现象**：`:core:database:testDebugUnitTest` 在 10 分钟内没有任何输出。

**根因**：Robolectric 在**运行时**（不是依赖解析时）下载 `android-all-instrumented` jar。
受限网络下它会长时间挂起，且 Gradle 侧看不到任何进度。

**修复**：把这批测试移到 `src/androidTest`，在模拟器上跑。它们验证的是真实 SQLite 实现，
可信度反而更高；启动只要 0.6 秒。

**教训**：**测试基础设施的失败和测试的失败要区分开。** 前者会让团队逐渐无视红灯，
比没有测试更危险。

### A10. 退款模式下分类列表错用了收入分类 🟠 ✅

**现象**：编辑一笔餐饮支出 → 点"退款" → 分类栏显示的是「工资/奖金/理财/红包」。

**根因**：退款在账务上是 `INCOME`（所以金额从支出口径里扣），于是分类下拉按 `mode` 取了收入分类。
但**退款必须挂在原支出的分类上**，否则它的金额既扣不到那笔消费的占比里，还会把"工资"这类
收入分类的金额算进去。

**修复**：分类列表的类型由"是否退款"决定（退款 → 支出分类），与 `type` 字段解耦。

**教训**：**一个字段同时承担两种含义（账务方向 vs 统计归属）时，界面要按语义取，而不是按字段取。**

### A11. 日小计忽略退款，与月合计互相矛盾 🟠 ✅

**现象**：当天有一笔 745 支出和它的 745 退款，列表显示
`今天 · 11月6日  支出 ¥745.00`，但顶部月度支出没变。

**根因**：Kotlin 侧按 `type == EXPENSE` 求和，而 SQL 聚合用的是"支出减退款"。
同一份数据两套口径 —— 而且这不是边缘情况，退款当天必然触发。

**修复**：日小计改用与 SQL 完全相同的规则（支出加、退款减、转账忽略）。

**教训**：**同一个业务口径有两处实现，迟早会打架。**
本项目的规则是"支出减退款"，它必须出现在每一个展示支出的地方。

---

### A12. 退款保存后回到的是上一层编辑页 🟠 ✅

**现象**：编辑支出 → 点退款 → 保存 → 不是回到列表，而是又回到那笔支出的编辑页。

**根因**：退款编辑器是压在支出编辑器之上的第二个 destination，`popBackStack()` 只弹掉最上面一层。

**修复**：退款模式保存后 `popBackStack(Transactions, inclusive = false)`，直接回列表。

**教训**：**从 A 打开 B 再保存，用户期望回到的是出发点，不是 A。** 这类栈深度问题在任何
"编辑中再发起编辑"的流程里都会重现。

---

### A13. 编辑预算会把创建时间改成"现在" 🟡 ✅

**现象**：改一次预算限额，`created_at` 被重写成当前时间。

**根因**：Room 的 `@Upsert` 在插入冲突后是**全列 UPDATE**（已核对生成的
`BudgetDao_Impl.kt`，走 `EntityUpsertionAdapter`）。调用方按"新建"的语义传入 `createdAt = now`，
编辑时就把原始创建时间覆盖掉了。代码里的注释当时还写着"@Upsert 会保留原值"——**注释是对的相反**。

**修复**：DAO 增加 `upsertPreservingCreatedAt`，在 `@Transaction` 内先读原值再写回；
并用一条真机测试锁定"编辑后 `created_at` 不变"。

**教训**：**ORM 的"便利方法"语义要读生成代码确认，不能靠名字推断。**
另外，写着"会保留"的注释如果没被测试验证过，它只是在传播一个假设。

---

### A14. 回收站首条记录被顶栏遮住 🟠 ✅

**现象**：回收站里明明有 1 条记录，页面上只看到"恢复 / 彻底删除"两个按钮，分类、金额、时间全不见。

**根因**：`Scaffold` 已经为 TopAppBar 预留了 `innerPadding`，空态分支用了它，但**列表分支忘了**
——`LazyColumn` 从屏幕顶端开始绘制，第一张卡片的上半部分被顶栏盖住，只露出下半部分的按钮。

**修复**：把 `innerPadding` 应用到 `LazyColumn` 本身。

**教训**：`Scaffold` 的 `innerPadding` 必须作用到**每一个**内容分支。
它看起来像"可选的留白"，实际是"内容不被系统栏遮挡"的契约；
漏用不会崩，只会安静地把内容画到别人底下。

### A15. CSV 导出：公式注入、编码、逗号三处都会毁掉文件 🟠 ✅

**风险**：导出的 CSV 看起来"成功"，但用户打开后是不可用的数据。

三处独立的问题，都不是崩溃，而是**安静地毁掉导出结果**：

| 问题 | 后果 | 处理 |
| --- | --- | --- |
| 备注以 `=`/`+`/`-`/`@` 开头 | Excel/Numbers 当公式执行（CSV 注入） | 前置 `'` 中和 |
| 无 UTF-8 BOM | Excel（Windows）按本地代码页解释，中文全部乱码 | 文件头写 `﻿` |
| 备注含 `,` / `"` / 换行 | 列错位，后面每一列都串了 | RFC 4180 引号转义 |

**验证**：12 条单测覆盖转义与注入；真机导出后用 Python `csv` 解析，确认 **11 列 × 159 行全部一致**、
无货币符号、BOM 在首位、`
` 数量 = 160 且没有重复 ``。

**教训**：导出功能的"成功"不是文件生成了，而是**目标程序能正确读出来**。
验收必须用解析器跑一遍，而不是看文件大小。

## B. 已知未修复（按严重度排序）

### B1. 时区变化会重排历史数据的分桶 🔴 📋

`occurred_at` 存 epoch millis，按天聚合时用 SQLite 的 `'localtime'`。
**结果：用户在旅行中切换时区，同一条流水可能换到另一天/另一周/另一月。**

- 影响：跨时区旅行者的月度报表数字会变；国际用户的"本月"边界漂移
- 为什么当初这么选：用户认为"23:30 买的算今天"，即时区本地日更符合直觉
- 待决策：是否给事务存一个 `local_date` 冗余列（写入时固化），使历史永不漂移
- 检测：现有测试用固定时区，**覆盖不到**这个场景

### B2. 金额溢出抛未捕获异常，会崩溃 🔴 ⚠️

`Money.plus/minus/times` 用 `Math.addExact` / `subtractExact` / `multiplyExact`，
溢出时抛 `ArithmeticException`。**全仓库没有任何捕获点。**

- 触发条件：导入超大金额（CSV 里 `1e18` 级别的数字）、乘以手滑的数量
- 实际风险：手工输入几乎不可能触发；**导入是唯一现实入口**
- 缓解：导入时做范围校验（建议上限 ±10^13 分，即约 1000 亿元），并在解析层 `runCatching`

### B4. 搜索用未转义的 `LIKE '%q%'` 🟠 ✅

```sql
AND (:query IS NULL OR note LIKE '%' || :query || '%')
```

两个问题：

1. **通配符未转义**：用户搜 `%` 会匹配全部记录，搜 `_` 会匹配任意单字符 —— 结果与用户意图不符
2. **无法走索引**：前置 `%` 导致全表扫描，5 万条后明细搜索会明显卡顿

- 已缓解：输入转义 `%` `_` `\`，搜索使用 Paging 3 分页。
- 后续：数据量明显增长后换 FTS5（`note` / 分类 / 账户建全文索引）。

### B5. 预算进度存在 N+1 查询 🟠 ⚠️

`BudgetRepositoryImpl.observeProgress` 对**每个预算**依次执行 2~3 个 suspend 查询
（子分类展开 + 区间汇总）。10 个预算 ≈ 30 次查询，且每次流水变化都会整体重跑。

- 缓解：改为单条 SQL 用 `GROUP BY budget` 一次算完，或对 `spentInPeriod` 结果做批量合并
- 检测：目前无性能测试，只能靠代码评审发现

### B6. 进程死亡后图表/预算选择状态丢失 🟠 ⚠️

粒度（周/月/年）与系列（支出/收入/两者）存在 ViewModel 里，**未进 `SavedStateHandle`**。
系统回收进程后回来，用户的选择会重置为默认。

- 与文档 §4.6 的"不能放在 `remember`"是同一类问题的另一半：**ViewModel 能扛旋转，扛不住进程死亡**
- 缓解：`SavedStateHandle` 存 `granularity.name` / `mode.name`

### B7. 归档分类的历史流水显示为"已删除分类" 🟡 ⚠️

`StatsRepositoryImpl.observeCategoryBreakdown` 用 `categoryDao.observeActive()`（只含未归档）
做名称映射，归档分类查不到名字 → 回落成"已删除分类"。

- 影响：视觉与文案不准确（分类还在，只是归档），不影响金额
- 缓解：映射改用 `observeAll()`，并在 UI 上对归档分类加视觉弱化

### B8. `spentInPeriod` 的空列表 `IN ()` 无断言 🟡 ⚠️

`categoryId != null` 但 `categoryIds` 为空时，SQLite 的 `IN ()` 恒为 false → 预算已用金额为 0。
当前调用路径不会产生空列表（至少含自身 id），但没有任何地方**保证**这一点。

- 缓解：在 DAO 或 Repository 加 `require(categoryIds.isNotEmpty() || categoryId == null)`

### B9. 软删除与未来唯一索引的冲突（预防） 🟡 📋

现在没有唯一索引。一旦加入（如"同一天同一账户同一金额"去重），**软删除行仍会占位**，
导致用户删除后无法重新录入同样的记录。

- 缓解：若加唯一约束，必须把 `deleted_at` 纳入索引键；或部分索引 `WHERE deleted_at IS NULL`

### B10. `Money.format()` 在列表项里创建格式化器 🟡 ⚠️

`NumberFormat.getCurrencyInstance()` + 设置 `currency`，每个金额字符串调用一次。
百条列表 = 百次对象创建。

- 缓解：按币种缓存 `NumberFormat`；注意 `NumberFormat` 非线程安全，需每线程/每次 clone

## C. 安全与隐私风险

### C1. 数据库明文存储 🔴 📋

`tallybook.db` 未加密。设备被 root、或备份文件被拷走，财务数据直接可读。

- 已做的：`allowBackup="true"` 但 `backup_rules.xml` / `data_extraction_rules.xml` 排除了 DB 文件
- 风险残留：**排除规则依赖文件名与表名的一致性**。将来改 `TallyDatabase.NAME` 而忘记同步
  XML，云备份就会把明文账本传上去，且**没有任何测试会失败**
- 缓解：加一条构建期检查（在 Gradle 任务里比对 `NAME` 常量与 XML 内容）；
  加密走 SQLCipher + Keystore（Phase 5，做成可选开关）

### C2. 截图与最近任务缩略图泄漏 🟠 ⚠️

未设置 `WindowManager.LayoutParams.FLAG_SECURE`（已确认全仓库无此调用）。
用户切到最近任务、或截图分享时，账本明细完整可见。

- 缓解：隐私锁开启时同时加 `FLAG_SECURE`（但会导致无法截图，需给用户开关）

### C4. 导出与备份文件为明文 🟠 📋

CSV/JSON 备份含全部财务记录，落盘即明文。用户可能上传到网盘。

- 缓解：提供"加密备份"选项（口令 → PBKDF2/Argon2 → AES-GCM），并在 UI 明示风险

### C5. SAF 授权未持久化 🟠 ⚠️

Phase 4 的自动备份需 `takePersistableUriPermission`，否则**重启后 URI 失效**，
备份静默失败。这类失败不报错，用户以为一直在备份。

- 缓解：申请 `FLAG_GRANT_PERSISTABLE_URI_PERMISSION`，并在备份成功后记录时间戳供 UI 展示

## D. 平台与生态风险

| 编号 | 风险 | 严重度 | 说明与对策 |
| --- | --- | --- | --- |
| D1 | Android 13+ 通知需运行时授权 | 🟠 | `POST_NOTIFICATIONS` 未申请则预算提醒完全不生效，且**无提示** |
| D2 | Android 12+ 精确闹钟受限 | 🟠 | `SCHEDULE_EXACT_ALARM` 默认拒绝；预算提醒用 WorkManager 可绕过，但会有分钟级延迟 |

| D4 | Gradle 发行版下载受阻 | 🟠 | `distributionUrl` 指向 `services.gradle.org`（会 302 到 GitHub）。国内首次 clone 可能卡住。建议文档中给出镜像配置或改用本地发行版 |
| D5 | `minSdk 26` 覆盖面 | 🟡 | 排除 Android 7.x 及以下（存量约 1%）。换来的是无需 desugaring，取舍合理但应在发布说明中写明 |
| D6 | 动态取色改变品牌色 | 🟡 | Android 12+ 默认跟随壁纸，品牌识别弱。可在设置中提供"跟随系统/固定品牌色" |
